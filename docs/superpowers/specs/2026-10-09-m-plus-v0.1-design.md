# Ka0s Premade Groups Filter Extension — M+ v0.1 design

Date: 2026-10-09 · Status: approved in chat, pending spec review · Scope: Retail, Mythic+ only

## 1. Intent

A companion addon to Premade Groups Filter (PGF) that adds a few Mythic+ conveniences PGF does not
offer, implemented by driving PGF's own UI state and Advanced Filter Expression rather than by
replacing its filtering. Success = with one click on **Apply**, PGF's dungeon checkboxes, Blizzard's
advanced filter, and PGF's expression all reflect the chosen options and a search runs.

What the user asked for (verbatim intent):

1. Target every dungeon the player has **not timed at or above** a user-entered key level N.
2. Filter groups by **server region** (multi-select).
3. Exclude groups that already have **my spec**, and/or **my class + role**.
4. All options combine with AND. Apply button applies and searches. Settings persist **per character**.
5. Hard dependency on PGF: the addon must not load without it.
6. Extras chosen for v1: **experienced leader**, **max group age**, **named presets**.

## 2. Constraints and findings that shape the design

| Finding | Consequence |
|---|---|
| `LFGListFrame.SearchPanel.SearchBox` has `securityDisableSetText`; `SetText` from addon code errors (verified in-game by the user). Group titles are protected. | The addon **cannot** write `N-N` into the search box and cannot filter on key level by title. It shows a read-only, auto-selected `N-N` field next to Apply for Ctrl+C → Ctrl+V. |
| PGF exposes its private namespace as `PremadeGroupsFilter.Debug` (Init.lua:27); `Main.lua` calls `PGF.PutPremadeRegionInfo(env, leaderName)` per search result through that table. | A `hooksecurefunc` post-hook there is the single injection seam: it receives the per-result `env`. |
| PGF dungeon panel: `PremadeGroupsFilterDungeonPanel`, state `PremadeGroupsFilterState.c2f4.dungeon`, checkbox keys `dungeon1..8` are **positional** (index into `panel.cmIDs`, sorted by PGF's local `CMID_MAP.order`). | Map cmID → index by scanning `panel.Dungeons["Dungeon"..i].cmId` at apply time; never hard-code positions. |
| `DungeonPanel:TriggerFilterExpressionChange()` re-filters and runs `UpdateAdvancedFilters()`, which rewrites Blizzard's `C_LFGList` advanced filter from the checked dungeons. | Blizzard filter sync is free: tick PGF checkboxes, PGF writes Blizzard's filter. Writing Blizzard's filter ourselves would be overwritten. |
| PGF's expression = `true and <ui parts> and ( <normalized user text> )`; normalization strips `--` lines and joins lines. | Marker comments are safe; our block must be parenthesized together with the user's text so the user's `or` cannot change precedence. |
| `C_LFGList.Search` is hardware-event protected. PGF searches via `RefreshButton` → `LFGListSearchPanel_DoSearch`. | Search is triggered by `PremadeGroupsFilterDialog.RefreshButton:Click()` **inside our button's OnClick** (or a typed slash command). |
| PremadeRegions global `PremadeRegions.GetRegion(name)` drives PGF's region vars; it uses `GetCurrentRegion()` (1 = US, 3 = EU). | We replicate it: own realm map; inject region vars ourselves when PremadeRegions is not loaded. |
| Ka0s standard library-stack-§6 / toc-file-§1 forbid hard `Dependencies`. | **Documented deviation** (user requirement). Recorded in `docs/ARCHITECTURE.md` → Documented deviations. |
| Best timed level: `C_MythicPlus.GetSeasonBestForMap(cmID)` → `intimeInfo.level`. Season maps: `C_ChallengeMode.GetMapTable()` (may be nil until `CHALLENGE_MODE_MAPS_UPDATE`). | Targeting computed on the client, no Raider.IO dependency. |

## 5. Panel

A frame styled like PGF's dialog (`PortraitFrameTemplateMinimizable` with
`SetBorder("ButtonFrameTemplateNoPortraitMinimizable")`, portrait hidden, strata FULLSCREEN,
GameFontNormal headers, `UICheckButtonTemplate` checkboxes, PGF's own global templates where they
fit). Anchored `TOPLEFT→dialog BOTTOMLEFT`, `TOPRIGHT→dialog BOTTOMRIGHT`, so width tracks PGF.
Visible only when `PremadeGroupsFilterDialog` is shown **and** its active panel is the dungeon panel;
hidden otherwise (hooks on dialog `OnShow`/`OnHide` and `SwitchToPanel`). Collapsible to its title
bar (state in `profile`).

Rows, top to bottom:

1. **Key targeting** `[x]` · Key level `[14]` · readout of best timed per dungeon, targeted ones
   highlighted (e.g. `AOF 13  RLP 13  BV 13  KR 13` gold, others grey).
2. **Regions** `[x]` · toggle chips for the current portal (US: OCE LA CHI MEX BZL; EU: ENG GER FRA
   ITA SPA POR RUS). Section hidden (with a one-line note) on KR/TW/CN.
3. **Composition** `[x] No one with my spec` · `[x] No one with my class + role`.
4. **Experienced leader** `[x]` — leader has timed this dungeon at ≥ key level.
5. **Max group age** `[x]` `[15]` min.
6. **Presets** dropdown · Save · Save as… · Delete.
7. **Apply** (primary) · **Clear** · read-only `N-N` field (click selects all; tooltip says Ctrl+C,
   then paste into the search box).

## 6. Apply semantics

1. Refuse in combat (`InCombatLockdown()`), with a chat message.
2. **Dungeons** (if Key targeting on): targets = season dungeons with `bestTimed < N` (untimed = 0).
   - Empty targets → message "You have timed every dungeon at +N or higher", nothing applied.
   - Else set PGF `dungeonN = true` for targets, `false` for others (by cmID → index lookup).
   If Key targeting is off, PGF's dungeon checkboxes are left untouched.
3. **Expression**: clauses (each only when its option is on):
   - Regions: `( oce or chi )` (selected keys joined by `or`; empty selection → option ignored with a warning).
   - Spec: `pgfe_samespec == 0`.  Class + role: `pgfe_sameclassrole == 0`.
   - Experienced leader: `( mpmapintime and mpmapmaxkey >= N )`.
   - Max age: `age <= M`.
   Merge into PGF's expression state (see §7).
4. Write state in place, `panel:Init(panel.state)`, `panel:TriggerFilterExpressionChange()`.
   If the dungeon panel is not live, write `PremadeGroupsFilterState.c2f4.dungeon` directly (PGF
   applies it on the next panel switch) and skip the trigger.
5. Search: `PremadeGroupsFilterDialog.RefreshButton:Click()` when the click originated from our
   Apply button or `/pgfe apply`.
6. Update the `N-N` field and remember the option snapshot in `char`.

**Clear** removes our block (restoring the user's own text) and triggers a re-filter; it does not
touch dungeon checkboxes.

## 7. Expression block format

With user text `U` (non-empty, our block stripped first):

```
-- [pgfe] begin: managed by Ka0s PGF Extension (Apply rewrites, Clear removes)
( <clauses joined by " and "> ) and (
-- [pgfe] end
U
-- [pgfe] close
)
```

With `U` empty:

```
-- [pgfe] begin: managed by Ka0s PGF Extension (Apply rewrites, Clear removes)
( <clauses> )
-- [pgfe] end
```

After PGF's normalization this is `( clauses ) and ( U )` — the user's precedence cannot leak.
Stripping removes `begin..end` and, if present, the `close` marker line plus the single `)` line
that follows it. Re-apply is idempotent; a block that has been hand-edited into an unparseable shape
is reported and left alone (Apply aborts the expression step with a message). No clauses → no block.
Total length is checked against PGF's 2000-character edit-box limit.

## 8. Injected variables

Installed once at file load (standard: hooks at load, never AceHook):
`hooksecurefunc(PremadeGroupsFilter.Debug, "PutPremadeRegionInfo", fn)` (nil-guarded).

- When `PremadeRegions` is **not** loaded: `env.region = key or nil`, and every known region key set
  to `false` then `env[key] = true` — identical shape to PGF's plugin.
- Always: `env.pgfe_samespec = env[mySpecKeyword] or 0`, where
  `mySpecKeyword = spec:lower().."_"..classFile:lower().."s"` (PGF's formula, via
  `PremadeGroupsFilter.Debug.C.SPECIALIZATIONS[specID]`), and
  `env.pgfe_sameclassrole = env[ROLE_PREFIX[role].."_"..classFile:lower().."s"] or 0`
  (`dps`/`heal`/`tank`). Player spec/role cached and refreshed on `ACTIVE_PLAYER_SPECIALIZATION_CHANGED`.
- Stood down (disabled) → the hook returns immediately (expressions referencing `pgfe_*` then
  evaluate nil; the user is told to Clear or re-enable).

## 9. Realm map and maintenance

- Seed from PremadeRegions' `Regions.lua` (US + EU tables), normalized the same way.
- Cross-check against an independent list (warcraft.wiki.gg realm pages / Blizzard realm status) for
  OCE, LA, CHI, MEX, BZL, and EU language realms; disagreements recorded in
  `docs/realm-map-maintenance.md` with the chosen value and source.
- `tools/realm_map_diff.py` (LF, shebang): diffs `defaults/Realms.lua` against an installed
  PremadeRegions and prints additions/removals/changes; the doc gives the periodic procedure
  (new season / realm connections / new realms).
- Tests assert normalization, no duplicate keys, and only known region values.

## 10. Persistence

- `char.filters` — current options (key level, toggles, regions, age) — **per character** (user requirement).
- `global.presets` — named snapshots, shared by all characters.
- `profile` — master settings (enable, debug, minimap) and panel collapsed state.
- `global.schemaVersion`, migration runner per the standard.

## 11. Error handling

- PGF seam missing (renamed in a PGF update) → panel shows a single "PGF version not supported"
  line, Apply disabled, diagnostics report which seam failed. No Lua errors.
- Season data not ready → readout shows "loading…", request map info, refresh on
  `CHALLENGE_MODE_MAPS_UPDATE`/`MYTHIC_PLUS_CURRENT_AFFIX_UPDATE`.
- Unsupported portal → regions section hidden; other options still work.
- Over-length expression → abort with message.

## 12. Testing

- Headless (`lua tests/run.lua`) with WoW + PGF stubs:
  - Targeting: the user's character data — N=14 → {AOF, RLP, BV, KR}; N=15 → all 8; N=2 → none (message).
  - Expression: empty/non-empty user text, user text with `or`, idempotent re-apply, clear, manual
    damage to the block, length limit.
  - Regions: suffix/no-suffix leader names, normalization, unknown realm, portal gating.
  - Env injection: PremadeRegions present vs absent; `pgfe_*` values; stood-down no-op.
  - Bridge: cmID→index mapping with shuffled order; live panel vs stored state path.
  - Presets round-trip; standard kit suites (surface parity, vendor sync, disabled, eol, prose, diagnostics).
- `luacheck .` 0/0; lizard CCN ≤ 15.
- `docs/smoke-tests.md` in-game checklist (attach/width, apply on N=14/15, Blizzard filter shows the
  same dungeons, region results, spec exclusion, combat refusal, PGF disabled → addon not loaded).
